## 1. Головне правило захисту від витоку (Zero-Leak Check)

| Тип перевірки | Що шукаємо | Результат | Примітка |
| :--- | :--- | :--- | :--- |
| **Паролі до Neon DB** | Рядки на зразок `postgres://...neon.tech` у коді | 🟢 Чисто | Рядки з'єднання мають бути ТІЛЬКИ в `.env.local` |
| **Ключі API та токени** | Секретні ключі Vercel, WebAuthn, JWT секрети | 🟢 Чисто | Всі секрети отримуються через `process.env` |
| **Контроль `.gitignore`** | Чи заблоковано файли `.env*` від потрапляння на GitHub | 🟢 Налаштовано | Файли `.env`, `.env.local` не підуть у коміт |

---

## 2. Перевірка бази даних Neon (SQL & Data Access)
- [ ] **SQL-ін'єкції**: Усі запити використовують параметризовані виклики (наприклад, `$1`, `$2`), а не склеювання рядків.
- [ ] **Адмінські права**: Ролі з правами адміністратора обмежені та використовують захищені сесії / WebAuthn.
- [ ] **Паролі користувачів**: Зберігаються виключно у захешованому вигляді.

---

## 3. Налаштування для Vercel
- [ ] Секретні змінні (наприклад, `DATABASE_URL`) додано безпосередньо в панелі **Vercel Settings ➔ Environment Variables**.
- [ ] Публічні змінні мають префікс `NEXT_PUBLIC_` (або `VITE_`), і вони НЕ містять паролів.
